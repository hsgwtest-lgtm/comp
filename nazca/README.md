# nazca — 8-Bit GPS Art & Free Doodle

歩いた軌跡で街に絵を描く、ドット絵（レトロゲーム風）の GPS アート PWA です。
社内の健康向上プログラム向けに、毎日 16:00 更新の **DAILY CHALLENGE（お題チャレンジ）** と、
自由に描ける **FREE DOODLE（フリーお絵描き）** の 2 モードを備えています。

テーマは「**地球上の笑顔の回数を増やしていく**」。2 日に 1 回は笑顔のお題（**SMILE DAY**）になり、
散歩中に見つけた「顔に見えるモノ」は **SMILE CAM** で撮って共有できます（v2.3）。

- フロントエンド: GitHub Pages（ビルド不要の素の JavaScript / ES Modules）
- バックエンド: Firebase（匿名認証 + Cloud Firestore）
- Firebase 未設定のままでも **ローカルモード**（この端末だけに保存）で全機能を試せます

公開 URL: `https://hsgwtest-lgtm.github.io/comp/nazca/`
（旧 URL `…/comp/` は自動でここへ転送されます。ホーム画面に追加済みの場合は、新しい URL から追加し直してください）

## 機能（仕様書との対応）

| 仕様 | 実装 |
| --- | --- |
| ピクセルアートの世界観 | 2 種類のドットフォント（同梱）、角の欠けたウィンドウ枠、限定パレットに減色したドット絵地図、8bit 効果音 |
| MODE A: DAILY CHALLENGE | 日本時間 16:00 に切り替わる日替わりお題。**笑顔のお題（15 種）と通常のお題（29 種）が 1 日おき**（v2.3）。**PTS = 正確さ（0.0〜100.0%）× 大きさの倍率（×1.00〜×2.00）× 10** で採点し、HIGH SCORE 風ランキングを表示 |
| MODE B: FREE DOODLE | お題なしで歩いて描き、タイトルを付けてフリーギャラリーに投稿 |
| MAP MODE / SKETCH-ONLY | 投稿時に選択。SKETCH-ONLY は緯度経度を破棄し、0〜1000 の相対座標の形だけを保存 |
| 1. MODE SELECT | タイトルロゴ、本日のお題（地上絵風アニメーション）、次の 16:00 までのカウントダウン。笑顔の日は **SMILE DAY**、翌日が笑顔の日なら **NEXT: SMILE DAY** |
| 2. TRACKING | お題ガイド表示、地図/スケッチ切替、START / PAUSE / RESUME / FINISH、GPS 精度表示。カメラボタンで計測を止めずに SMILE CAM |
| 3. RESULT & POST | DAILY は **MATCH**（軌跡を回してお題に重ねる）→ **SCORE!** で採点。歩行距離、公開モードの選択とプレビュー、POST |
| 4. GALLERY & RANKING | 日別ハイスコアランキング（前日以前も閲覧可。笑顔の日は SMILE DAY）、フリーギャラリー、**SMILES**（撮影した笑顔）、LIKE / STAR / 1UP / GG スタンプ。MAP の作品は**その絵だけ**を作者が決めた向き・中心で表示 |
| EXPLORE（v2） | 地図を探索して、MAP MODE の作品（地上絵）を見つける。SIGNAL・RADAR（方向の矢印）・現在地/コンパス追従・現地を訪れると VISITED。世界中の本物の地上絵 40 か所（v2.1）も。ATLAS（図鑑）で解説・WARP。MAP 公開の写真は顔のピン（ON / OFF） |
| SMILE CAM（v2.3） | 顔に見えるモノ（コンセント・車の正面・マンホール…）を正方形で撮影（1〜4 倍ズーム）→ 端末内で 64×64・16 色のドット絵に → タイトル・ひとことを付けて GALLERY のみ／MAP 公開で投稿。タイトル画面・`#/cam`（ホーム画面のショートカット）・計測画面から |
| 笑顔の回数（v2.3） | 笑顔のお題の DAILY 投稿数（笑顔地上絵）＋撮影した笑顔の投稿数を `smile_log` に記録（画面には未表示） |

そのほか:

- **地図は 2 本指で回転**できます（ピンチの中点が軸。回したまま拡大・縮小も可）。北向きに戻すときは方位ボタン
- **現在地ボタン**（計測画面・EXPLORE 共通）: 押すたびに「現在地に追従（北が上）→ コンパス（進行方向が上）→ 北が上」と切り替わります（`js/compass.js`）
- EXPLORE のみんなの作品は、投稿ごとに決まるレトロな派手色＋暗いふちどりで表示（自分の作品はミント、世界の地上絵は砂色）
- **GUIDE**: お題を画面中央に重ね、地図を動かして位置、ピンチで大きさ、2 本指・±1° ボタンで向きを決めて SET。
  大きさと 1 周の距離の目安が出ます。SET 後は MOVE でやり直せます
- **完成後の向き・中心の調整**: 結果画面の ADJUST で、作品の中心点（地図をドラッグ）と向き（2 本指・±1°・±15°）を決めて投稿。
  DAILY はお題に合わせて自動で正立させた向きが初期値になります。MAP は地図ごと回して表示、SKETCH-ONLY は形そのものを回して保存します
- **PAUSE 中の移動は線にならない**ので、目や窓など一筆書きできない線も描けます
- 計測中は画面の自動ロックを防止（Screen Wake Lock）。途中で閉じても端末内に保存され、CONTINUE で再開できます
- GPS の精度が悪い測位・静止時のブレ・瞬間移動（飛び）は自動で除外します
- 投稿の送信に失敗しても作品は端末に残り、同じ作品が二重に投稿されることはありません
- オフラインでもアプリ本体は起動します（Service Worker）

### 笑顔のお題と SMILE DAY（v2.3）

- 笑顔のお題 30 種（`js/challenges.js` の `SMILE_TEMPLATES`、id は `smile-01`〜`smile-30`、`theme: 'smile'`）。
  顔の輪郭はなく、目と口だけです（ほとんど 3 筆。PAUSE で次の線へ）。既存の `smile`（四角い輪郭の顔）は別物として残しています
- `pool`: `rotation`（15 種・ローテーションで出題）／ `normal`（9 種・将来の入れ替え候補）／ `advanced`（6 種・特別な日用）
- `ORDER_V3_FROM`（公開した日のチャレンジ日）から、**チャレンジ日の 1 日おき**に 笑顔 → 通常 → 笑顔 … と出題します。
  `i = dayNumber(その日) − dayNumber(ORDER_V3_FROM)` が偶数なら `SMILE_ORDER[(i / 2) % 15]`、奇数なら `ORDER_V3[((i − 1) / 2) % 29]`
  （`ORDER_V3` は `ORDER_V2` から `smile` を除いた 29 種）。`SMILE_ORDER` は描きやすい顔から、口の形が交互になる順に並べています
- 笑顔の日は、タイトル・計測画面・ランキングの日付に **SMILE DAY**、前日のタイトルに **NEXT: SMILE DAY** が出ます
- 笑顔のお題の DAILY 投稿には `theme: 'smile'` が付き、`smile_log` に記録されます
- 目や口が小さいので、顔の幅 200m 以上（できれば 300m くらい）で描くのがおすすめです（下の「採点ロジック」参照）

### SMILE CAM（v2.3）

- 正方形の枠で撮影し、**枠の中に見えている範囲がそのまま保存**されます。ピンチかスライダーで 1〜4 倍に拡大
  （カメラのズームが使える端末はそれを使い、iPhone などはデジタルズームで中央を切り出し）
- カメラが使えない・許可されないときは、写真を撮る／選ぶ → 正方形の位置と拡大率を決める画面になります
- 撮った写真は端末内で 64×64・16 色のドット絵にし（4×4 の網点ディザ）、元の写真は保存しません。
  パレットと見本は `docs/smile-palette-samples.png`（パレットは `js/smilepix.js` の `PHOTO_PALETTES`。データには版番号 `pal: 1` だけを保存）
- 保存形式: 1 画素 = パレット番号 4 ビット → 2,048 バイト → base64 2,732 字（`pixels`）
- 計測中は計測画面のカメラボタンから（撮影中も GPS の記録は続きます）。撮影が終わると計測画面に戻ります
- 送信に失敗しても端末に残り、SMILE CAM を開くと続きから送れます（同じ写真が二重に投稿されることはありません）

### 世界の地上絵（EXPLORE・v2.1）

`js/ancient.js` に 12 か国・40 か所の本物の地上絵を収録しています（ナスカ 11・パラカス・アタカマの巨人・サーペント・マウンド・
アフィントンの白馬・ストーンヘンジ・ウシトガイ・サハラの目・マリーマン・大仙古墳・京都と箱根の大文字・田んぼアート・海老名の秋葉山古墳群 など）。

- 地図をズームして見つけると、国・年代・大きさと、かんたんな歴史・雑学（VIEW）が読めます
- **ATLAS**（図鑑）で発見状況を国別に一覧。まだ見つけていない地上絵は **WARP** で近くまで飛び、SIGNAL と RADAR でさがします
- 斜面に描かれたもの（白馬・大文字など）は、ふもとから見て正立する向き（`rot`）で地図に置いています
- 形はゲーム用に簡略化した線画、位置はおおよそです。位置・大きさ・年代は各国の文化財機関、UNESCO、Wikipedia、論文などで確認しました

## 採点ロジック（`js/score.js`）

1. お題と軌跡を弧長で等間隔に再サンプリング
2. お題を外接矩形で正規化し、軌跡の **向き** を決めてから **拡大縮小・平行移動** を最適化して重ねる
   - 向きは採点前の MATCH 画面でプレイヤーが回して合わせられる（ドラッグ・2 本指・±1°/±15°）。
     初期値は 360° 探索でいちばん重なる向き（GUIDE を置いた向きも候補に入れる）
   - 歩く場所・大きさ・向きは自由。鏡像は不可
3. 双方向の平均距離 D =（お題→軌跡：描き残し ＋ 軌跡→お題：はみ出し）÷ 2
4. 正確さ `score = 100 / (1 + (D / 0.04)^3)`
5. 大きさ: 重ねた絵の実寸で測ったお題の線の長さ `sizeM`（歩いた距離ではないので、往復しても増えない）。
   倍率 = `1 + log2(sizeM / 100) / log2(32)`（100m で ×1.00、400m で ×1.40、1.6km で ×1.80、3.2km 以上で ×2.00）
6. **PTS = 正確さ × 倍率 × 10**（最高 2,000）。ランキングは PTS 順。PTS 導入前の投稿は倍率 ×1.00 として扱います

`node tests/score.test.mjs` で検証できます（どの向きで歩いても、お題どおりなら ≈ 99%、碁盤目の街路で近似 ≈ 93%、
半分だけ ≈ 21%、別のお題 ≈ 26%、でたらめ ≈ 18%）。
ランク表示は S ≥ 90 / A ≥ 75 / B ≥ 60 / C ≥ 40 / D。

笑顔のお題（同じテスト）: お題どおりに歩くと 99.3〜99.8%、別の笑顔 29 種の平均は 17〜43%（全体平均 ≈ 31%）、口だけ歩くと 2〜32%。
ただし **目の形だけが違う顔どうし（例: NIKO と WINK）は 90% 以上**になります（目が小さく、線の長さの大半が口のため）。
計測と同じ GPS フィルタ込みのシミュレーション（住宅街の誤差）では、顔の幅 200m で平均 95%（全 30 種 91% 以上）、120m で平均 83% です。

## プライバシー設計

- 計測中の生データ（緯度経度）は端末の中（localStorage）だけに保存され、投稿または破棄した時点で削除されます
- **SKETCH-ONLY** は投稿前に端末内で緯度経度を捨て、形を 0〜1000 の格子に正規化したデータだけを送信します。
  Firestore ルールでも、SKETCH-ONLY の投稿に位置情報（`geo`）を含めることを禁止しています
- **MAP MODE** を選んだときだけ、地図表示用の緯度経度（約 1m 単位に丸めて簡略化）と表示の中心・向き（`view`）を保存します。
  結果画面では「歩いた場所が地図ごと公開される」ことを明示しています
- EXPLORE に現れるのは MAP MODE の作品だけです。発見・訪問の記録は端末の中だけに保存されます
- **SMILE CAM**
  - 撮影時に「人の顔、ナンバープレート、撮影が禁止されている場所、個人を特定できるものは撮らないでください」と表示します
  - 写真は端末内で 64×64・16 色のドット絵に減色し、**元の写真は送信も保存もしません**（canvas で描き直すので EXIF も残りません）
  - 公開範囲の初期値は **GALLERY**（ギャラリーのみ）。このときは**位置情報を取得しません**。Firestore ルールでも gallery の投稿に `pos` を含めることを禁止しています
  - **MAP** を選んだときだけ、投稿の直前に現在地を 1 回取得し、1e-5 度（約 1m）に丸めて `pos` に保存します。画面で「撮った場所が地図に公開される」ことを明示しています
  - カメラは撮影画面を離れたとき・アプリを切り替えたときに止めます

## セットアップ

### 1. GitHub Pages を有効にする

リポジトリの **Settings → Pages → Build and deployment** で
Source: `Deploy from a branch`、Branch: `main` / `/ (root)` を選んで保存します（アプリは `nazca/` フォルダ）。

### 2. Firebase をつなぐ（社内で共有する場合）

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成
2. **Authentication → Sign-in method** で「匿名」を有効化
3. **Authentication → Settings → 承認済みドメイン** に `hsgwtest-lgtm.github.io` を追加
4. **Firestore Database** を作成（ロケーションは `asia-northeast1` など）
5. **Firestore → ルール** に `nazca/firestore.rules` の内容を貼り付けて公開
   （Firebase CLI を使う場合は `nazca/` で `firebase deploy --only firestore:rules`）
6. **プロジェクトの設定 → マイアプリ** でウェブアプリを追加し、表示された `firebaseConfig` を
   `nazca/js/config.js` の `FIREBASE_CONFIG` に貼り付け
7. `nazca/sw.js` の `VERSION` を上げてからコミット・プッシュ

> **v2.3 へ更新するとき（公開の順番）**: ① `firestore.rules` を Firebase コンソールの **Firestore → ルール** に貼り直して「公開」→ ② アプリを push。
> v2.2 で `pts`・`sizeM`・`theme`・`smile_posts`・`smile_log` を追加し、v2.3 で `smile_log` を「本人の実際の投稿 1 件につき 1 件」に絞りました。
> 貼り直す前でも DAILY の投稿はできます（新しい項目を外して再送し、投稿後にその旨を表示。その投稿は倍率 ×1.00・笑顔の回数に入りません）。
> SMILE CAM の投稿と笑顔の回数の記録は、ルールを貼り直すまで送れません（写真と記録は端末に残り、あとで再送されます）。

複合インデックスは不要です（日別ランキングは `dayKey`、EXPLORE は `publish == 'map'` の等価検索、ギャラリーは `createdAt` の並べ替えのみ）。
EXPLORE は各コレクションから MAP の作品を最大 500 件ずつ読み込みます。作品がそれ以上に増えたら、地域ごとの検索（geohash など）に切り替えてください。

### コレクション

| パス | 内容 |
| --- | --- |
| `daily_posts/{id}` | デイリー投稿（`dayKey`, `challengeId`, `score`, `pts`, `sizeM`, `shape`, `geo`・`view`※MAP のみ, `theme: 'smile'`※笑顔のお題のみ, `reactions` …） |
| `free_posts/{id}` | フリー投稿（`title`, `shape`, `geo`・`view`※MAP のみ, `reactions` …） |
| `smile_posts/{id}` | 撮影した笑顔（`kind: 'smile'`, `uid`, `name`＝投稿者名, `title`, `comment`, `pixels`, `pal`, `publish`＝`gallery` / `map`, `pos`※MAP のみ, `reactions`, `v`, `createdAt`） |
| `smile_log/{id}` | 笑顔の回数の記録（追記専用・ID = 投稿 ID。`uid`, `type`＝`geoglyph` / `found`, `refId`, `dayKey`※geoglyph のみ, `createdAt`） |
| `challenges/{YYYY-MM-DD}` | お題の上書き（任意。`templateId` で組み込みのお題を指定、または `strokes` を直接書く） |
| `users/{uid}` | 表示名 |

### 笑顔の回数（`smile_log`）

- **笑顔地上絵**（`type: 'geoglyph'`）: 笑顔のお題の DAILY 作品を投稿するたびに 1 件（同じ人・同じ日でも投稿ごとに 1）。FREE DOODLE は数えません
- **見つけた笑顔**（`type: 'found'`）: SMILE CAM で投稿するたびに 1 件（公開範囲に関係なく）
- **笑顔の回数** = `smile_log` の件数（geoglyph ＋ found）。スタンプは含めません。**投稿を削除しても記録は消えません**
- 取り出し方: Firebase コンソールの **Firestore → クエリ ビルダー** で `smile_log` を `createdAt`（期間）・`uid`・`type` で絞り込むと件数が出ます
- ルールで、記録は**本人の実際の投稿 1 件につき 1 件だけ**作れるようにしています（ID = 投稿 ID・作成のみ・更新と削除は不可）
- 注意: 匿名認証のため、端末やブラウザを変えると別のユーザーとして数えられます。端末側で書き込む仕組みなので、厳密な不正対策にはなりません
- ローカルモードでは端末内（`nazca.local.smileLog`）に同じ形で記録します

### お題を差し替える（任意）

組み込みのお題は `js/challenges.js` で管理しています（通常のお題 30 種 `TEMPLATES`・笑顔のお題 30 種 `SMILE_TEMPLATES`）。

| 期間（チャレンジ日） | 順番 |
| --- | --- |
| 〜 2026-10-06 | `ORDER_V1`（20 種） |
| `ORDER_V2_FROM`（2026-10-07）〜 | `ORDER_V2`（30 種） |
| `ORDER_V3_FROM`（2026-10-07）〜 | 1 日おきに `SMILE_ORDER`（笑顔 15 種）と `ORDER_V3`（通常 29 種）。初日は笑顔 |

古い順番の分岐は、前日以前のランキングのお題が変わらないように残しています。順番を変えるときは `ORDER_V4_FROM` のように
**未来の日付から**新しい順番に切り替えてください。ランキングには、その日のお題と同じお題で採点されたスコアだけを表示します。

特定の日だけ別のお題にしたい場合は、Firestore に `challenges/2026-10-10`（その日 16:00 から翌 15:59 まで）
というドキュメントを作ります。組み込みのお題（笑顔の `advanced` など）を使うときは `templateId` だけで OK です
（`theme` なども引き継ぎ、SMILE DAY になります）。

```json
{ "templateId": "smile-27" }
```

線を直接書くこともできます。`"theme": "smile"` を書くと笑顔のお題（SMILE DAY）として扱います。

```json
{
  "name": "ROBOT",
  "ja": "ロボット",
  "theme": "smile",
  "strokes": [ { "p": [0, 0, 8, 0, 8, 8, 0, 8, 0, 0] }, { "p": [2, 3, 2, 4] } ]
}
```

`p` は x, y を交互に並べた折れ線です（画面座標・単位は任意。PAUSE でつなぐ線は別ストロークに）。

### 更新するとき

アプリのファイルを変更したら、`nazca/sw.js` の `VERSION` を必ず上げてください。
利用者のタイトル画面に **UPDATE** ボタンが表示され、押すと新しいバージョンに切り替わります
（計測中に勝手に再読み込みされることはありません）。

## 開発メモ

- ローカル確認: リポジトリのルートで `python3 -m http.server 8080` → `http://localhost:8080/nazca/`
- **デバッグモード**: URL に `?debug=1` を付けると計測画面に `AUTO WALK`（ガイドをなぞる擬似歩行）と
  `TAP`（地図をタップした地点へ移動）が出ます。机の上で一連の流れを試せます（タブを閉じるまで有効）
  - `?debug=1&odai=smile-05` のようにお題の id を付けると、そのお題で遊べます（タイトルに「(DEBUG)」。`&odai=` で解除）。
    このお題で描いた作品は**投稿できません**（ランキング・笑顔の回数・自己ベストの対象外）
  - AUTO WALK は GPS のフィルタを通らない理想的な歩行なので、採点はほぼ 100% になります。GPS の誤差込みの描きやすさは `node tests/score.test.mjs` の SMILE ODAI の表を見てください
- パソコンでは Shift + ホイールで地図を回転できます
- 採点テスト: `node tests/score.test.mjs`
- 地図は外部ライブラリを使わない自前のタイルマップ（`js/pixelmap.js`）です。OpenStreetMap のタイルを
  読み込み、レトロパレットに減色して 1 ドット = 2px で表示します
- アプリアイコンは `python3 tools/make_icons.py icons` で生成します（36×36 のドット絵：暗い土色の地面に色あせた黄土色のナスカのハチドリ）

## 制約・注意

- iPhone は画面が消えると GPS の記録が止まります（アプリは画面の自動ロックを防ぎますが、手動で消すと止まります）
- スコアは端末側で計算しています。不正対策を厳密にする場合は Cloud Functions での再採点を追加してください
- 匿名認証のため、端末やブラウザを変えると別プレイヤーになります
- コンパス（地図を進行方向に回す）は、iPhone では初回に「動きと方向」へのアクセス許可を求められます
- SMILE CAM: iPhone のホーム画面に追加した PWA では、カメラの許可を何度か聞かれることがあります（拒否した場合は「写真を撮る・選ぶ」で撮れます）。
  ホーム画面のショートカット（`#/cam`）から開くと計測画面を離れるため、計測中なら計測は一時停止になります（計測中は計測画面のカメラボタンを使ってください）
- 地図タイルは OpenStreetMap の公開タイルサーバーを使っています。利用者が多くなる場合は
  [タイル利用規約](https://operations.osmfoundation.org/policies/tiles/) に従い、
  商用のタイル配信サービスに `js/config.js` の `TILE_URL` を切り替えてください
