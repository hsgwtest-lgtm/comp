# nazca — 8-Bit GPS Art & Free Doodle

歩いた軌跡で街に絵を描く、ドット絵（レトロゲーム風）の GPS アート PWA です。
社内の健康向上プログラム向けに、毎日 16:00 更新の **DAILY CHALLENGE（お題チャレンジ）** と、
自由に描ける **FREE DOODLE（フリーお絵描き）** の 2 モードを備えています。

- フロントエンド: GitHub Pages（ビルド不要の素の JavaScript / ES Modules）
- バックエンド: Firebase（匿名認証 + Cloud Firestore）
- Firebase 未設定のままでも **ローカルモード**（この端末だけに保存）で全機能を試せます

公開 URL: `https://hsgwtest-lgtm.github.io/comp/nazca/`
（旧 URL `…/comp/` は自動でここへ転送されます。ホーム画面に追加済みの場合は、新しい URL から追加し直してください）

## 機能（仕様書との対応）

| 仕様 | 実装 |
| --- | --- |
| ピクセルアートの世界観 | 2 種類のドットフォント（同梱）、角の欠けたウィンドウ枠、限定パレットに減色したドット絵地図、8bit 効果音 |
| MODE A: DAILY CHALLENGE | 日本時間 16:00 に切り替わる日替わりお題（ドット絵線画 30 種のローテーション）。歩行軌跡との類似度を 0.0〜100.0% で自動採点し、HIGH SCORE 風ランキングを表示 |
| MODE B: FREE DOODLE | お題なしで歩いて描き、タイトルを付けてフリーギャラリーに投稿 |
| MAP MODE / SKETCH-ONLY | 投稿時に選択。SKETCH-ONLY は緯度経度を破棄し、0〜1000 の相対座標の形だけを保存 |
| 1. MODE SELECT | タイトルロゴ、本日のお題（地上絵風アニメーション）、次の 16:00 までのカウントダウン |
| 2. TRACKING | お題ガイド表示、地図/スケッチ切替、START / PAUSE / RESUME / FINISH、GPS 精度表示 |
| 3. RESULT & POST | DAILY は **MATCH**（軌跡を回してお題に重ねる）→ **SCORE!** で採点。歩行距離、公開モードの選択とプレビュー、POST |
| 4. GALLERY & RANKING | 日別ハイスコアランキング（前日以前も閲覧可）、フリーギャラリー、LIKE / STAR / 1UP / GG スタンプ。MAP の作品は**その絵だけ**を作者が決めた向き・中心で表示 |
| EXPLORE（v2） | 地図を探索して、MAP MODE の作品（地上絵）を見つける。SIGNAL・RADAR（方向の矢印）・現在地/コンパス追従・現地を訪れると VISITED。世界中の本物の地上絵 40 か所（v2.1）も。ATLAS（図鑑）で解説・WARP |

そのほか:

- **地図は 2 本指で回転**できます（ピンチの中点が軸。回したまま拡大・縮小も可）。北向きに戻すときは方位ボタン
- **GUIDE**: お題を画面中央に重ね、地図を動かして位置、ピンチで大きさ、2 本指・±1° ボタンで向きを決めて SET。
  大きさと 1 周の距離の目安が出ます。SET 後は MOVE でやり直せます
- **完成後の向き・中心の調整**: 結果画面の ADJUST で、作品の中心点（地図をドラッグ）と向き（2 本指・±1°・±15°）を決めて投稿。
  DAILY はお題に合わせて自動で正立させた向きが初期値になります。MAP は地図ごと回して表示、SKETCH-ONLY は形そのものを回して保存します
- **PAUSE 中の移動は線にならない**ので、目や窓など一筆書きできない線も描けます
- 計測中は画面の自動ロックを防止（Screen Wake Lock）。途中で閉じても端末内に保存され、CONTINUE で再開できます
- GPS の精度が悪い測位・静止時のブレ・瞬間移動（飛び）は自動で除外します
- 投稿の送信に失敗しても作品は端末に残り、同じ作品が二重に投稿されることはありません
- オフラインでもアプリ本体は起動します（Service Worker）

### 世界の地上絵（EXPLORE・v2.1）

`js/ancient.js` に 12 か国・40 か所の本物の地上絵を収録しています（ナスカ 11・パラカス・アタカマの巨人・サーペント・マウンド・
アフィントンの白馬・ストーンヘンジ・ウシトガイ・サハラの目・マリーマン・大仙古墳・京都と箱根の大文字・田んぼアート・海老名の秋葉山古墳群 など）。

- 地図をズームして見つけると、国・年代・大きさと、かんたんな歴史・雑学（VIEW）が読めます
- **ATLAS**（図鑑）で発見状況を国別に一覧。まだ見つけていない地上絵は **WARP** で近くまで飛び、SIGNAL と RADAR でさがします
- 斜面に描かれたもの（白馬・大文字など）は、ふもとから見て正立する向き（`rot`）で地図に置いています
- 形はゲーム用に簡略化した線画、位置はおおよそです。位置・大きさ・年代は各国の文化財機関、UNESCO、Wikipedia、論文などで確認しました

## 採点ロジック（`js/score.js`）

1. お題と軌跡を弧長で等間隔に再サンプリング
2. お題を外接矩形で正規化し、軌跡の **向き** を決めてから **拡大縮小・平行移動** を最適化して重ねる
   - 向きは採点前の MATCH 画面でプレイヤーが回して合わせられる（ドラッグ・2 本指・±1°/±15°）。
     初期値は 360° 探索でいちばん重なる向き（GUIDE を置いた向きも候補に入れる）
   - 歩く場所・大きさ・向きは自由。鏡像は不可
3. 双方向の平均距離 D =（お題→軌跡：描き残し ＋ 軌跡→お題：はみ出し）÷ 2
4. `score = 100 / (1 + (D / 0.04)^3)`

`node tests/score.test.mjs` で検証できます（どの向きで歩いても、お題どおりなら ≈ 99%、碁盤目の街路で近似 ≈ 93%、
半分だけ ≈ 21%、別のお題 ≈ 26%、でたらめ ≈ 18%）。
ランク表示は S ≥ 90 / A ≥ 75 / B ≥ 60 / C ≥ 40 / D。

## プライバシー設計

- 計測中の生データ（緯度経度）は端末の中（localStorage）だけに保存され、投稿または破棄した時点で削除されます
- **SKETCH-ONLY** は投稿前に端末内で緯度経度を捨て、形を 0〜1000 の格子に正規化したデータだけを送信します。
  Firestore ルールでも、SKETCH-ONLY の投稿に位置情報（`geo`）を含めることを禁止しています
- **MAP MODE** を選んだときだけ、地図表示用の緯度経度（約 1m 単位に丸めて簡略化）と表示の中心・向き（`view`）を保存します。
  結果画面では「歩いた場所が地図ごと公開される」ことを明示しています
- EXPLORE に現れるのは MAP MODE の作品だけです。発見・訪問の記録は端末の中だけに保存されます

## セットアップ

### 1. GitHub Pages を有効にする

リポジトリの **Settings → Pages → Build and deployment** で
Source: `Deploy from a branch`、Branch: `main` / `/ (root)` を選んで保存します（アプリは `nazca/` フォルダ）。

### 2. Firebase をつなぐ（社内で共有する場合）

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成
2. **Authentication → Sign-in method** で「匿名」を有効化
3. **Authentication → Settings → 承認済みドメイン** に `hsgwtest-lgtm.github.io` を追加
4. **Firestore Database** を作成（ロケーションは `asia-northeast1` など）
5. **Firestore → ルール** に `nazca/firestore.rules` の内容を貼り付けて公開
   （Firebase CLI を使う場合は `nazca/` で `firebase deploy --only firestore:rules`）
6. **プロジェクトの設定 → マイアプリ** でウェブアプリを追加し、表示された `firebaseConfig` を
   `nazca/js/config.js` の `FIREBASE_CONFIG` に貼り付け
7. `nazca/sw.js` の `VERSION` を上げてからコミット・プッシュ

> **v2 へ更新したとき**: `firestore.rules` に作品の向き（`view`）を追加しました。ルールを貼り直して公開してください。
> 貼り直す前でも投稿はできます（向きの情報だけ保存されず、投稿後にその旨が表示されます）。

複合インデックスは不要です（日別ランキングは `dayKey`、EXPLORE は `publish == 'map'` の等価検索、ギャラリーは `createdAt` の並べ替えのみ）。
EXPLORE は各コレクションから MAP の作品を最大 500 件ずつ読み込みます。作品がそれ以上に増えたら、地域ごとの検索（geohash など）に切り替えてください。

### コレクション

| パス | 内容 |
| --- | --- |
| `daily_posts/{id}` | デイリー投稿（`dayKey`, `challengeId`, `score`, `shape`, `geo`・`view`※MAP のみ, `reactions` …） |
| `free_posts/{id}` | フリー投稿（`title`, `shape`, `geo`・`view`※MAP のみ, `reactions` …） |
| `challenges/{YYYY-MM-DD}` | お題の上書き（任意） |
| `users/{uid}` | 表示名 |

### お題を差し替える（任意）

組み込みの 30 種は `js/challenges.js` の `TEMPLATES` と `ORDER_V2` で管理しています。
2026-10-06 までは旧ローテーション（20 種の `ORDER_V1`）、2026-10-07 からは 30 種の `ORDER_V2` を使います（過去のランキングのお題が変わらないように）。
お題を増やすときは、`ORDER_V3_FROM` のように **未来の日付から** 新しい順番に切り替えてください。
ランキングには、その日のお題と同じお題で採点されたスコアだけを表示します（古いバージョンのアプリで遊んだスコアが混ざらないように）。
特定の日だけ別のお題にしたい場合は、Firestore に `challenges/2026-10-10`（その日 16:00 から翌 15:59 まで）
というドキュメントを作ります。

```json
{
  "name": "ROBOT",
  "ja": "ロボット",
  "strokes": [ { "p": [0, 0, 8, 0, 8, 8, 0, 8, 0, 0] }, { "p": [2, 3, 2, 4] } ]
}
```

`p` は x, y を交互に並べた折れ線です（画面座標・単位は任意。PAUSE でつなぐ線は別ストロークに）。

### 更新するとき

アプリのファイルを変更したら、`nazca/sw.js` の `VERSION` を必ず上げてください。
利用者のタイトル画面に **UPDATE** ボタンが表示され、押すと新しいバージョンに切り替わります
（計測中に勝手に再読み込みされることはありません）。

## 開発メモ

- ローカル確認: リポジトリのルートで `python3 -m http.server 8080` → `http://localhost:8080/nazca/`
- **デバッグモード**: URL に `?debug=1` を付けると計測画面に `AUTO WALK`（ガイドをなぞる擬似歩行）と
  `TAP`（地図をタップした地点へ移動）が出ます。机の上で一連の流れを試せます（タブを閉じるまで有効）
- パソコンでは Shift + ホイールで地図を回転できます
- 採点テスト: `node tests/score.test.mjs`
- 地図は外部ライブラリを使わない自前のタイルマップ（`js/pixelmap.js`）です。OpenStreetMap のタイルを
  読み込み、レトロパレットに減色して 1 ドット = 2px で表示します
- アプリアイコンは `python3 tools/make_icons.py icons` で生成します（36×36 のドット絵：ナスカのハチドリと、線を描きながら歩く人）

## 制約・注意

- iPhone は画面が消えると GPS の記録が止まります（アプリは画面の自動ロックを防ぎますが、手動で消すと止まります）
- スコアは端末側で計算しています。不正対策を厳密にする場合は Cloud Functions での再採点を追加してください
- 匿名認証のため、端末やブラウザを変えると別プレイヤーになります
- コンパス（地図を進行方向に回す）は、iPhone では初回に「動きと方向」へのアクセス許可を求められます
- 地図タイルは OpenStreetMap の公開タイルサーバーを使っています。利用者が多くなる場合は
  [タイル利用規約](https://operations.osmfoundation.org/policies/tiles/) に従い、
  商用のタイル配信サービスに `js/config.js` の `TILE_URL` を切り替えてください
